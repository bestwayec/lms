## Verified findings and changes

- **SEC-001 FIXED (specific SSO path):** one-click SSO looked up an existing account by mutable username, attached an unlinked Telegram ID, and marked it verified. It could also reactivate an inactive account. SSO now resolves only the numeric ID and refuses inactive or legacy-unverified links. New IDs create separate student accounts; duplicate token use fails. Existing verified numeric links remain valid. The legacy teacher-contact path linked a teacher based only on phone suffix; it now directs users to the existing authenticated web linking flow. Private teacher/group lookup no longer falls back to username.
- **SEC-002 PARTIAL (binding and callbacks):** an unidentified caller, or any known teacher, could bind a group by code/name and silently replace another chat's binding. Binding now requires a verified, active LMS identity, the group's own teacher or platform admin, and Telegram creator/admin membership. Database writes are atomic, conflicting bindings are refused, and PostgreSQL serializes concurrent use of the same chat via an advisory transaction lock. Successful bindings are logged. Attendance start/finalize and test announcements check the group teacher; attendance callbacks require verified membership. Private report and grading callbacks check the current actor and object scope. This does not complete the unbind audit or make all attendance/score updates transactional and idempotent.
- **SEC-003 FIXED (identified hardcoded paths):** the formerly hardcoded Telegram ID granted admin rights and could auto-promote a new account to Django superuser on login/provisioning. Telegram IDs no longer grant roles; protected handlers and approval callbacks use active verified LMS roles. The privileged management command requires an explicit positive ID and rejects an account already linked to a different ID. The default notification recipient was removed, including a separate hardcoded payment-receipt destination. To receive admin alerts, the operator must explicitly configure `ADMIN_TELEGRAM_ID`; this setting does not grant privileges. Already-existing Django administrator roles are preserved.
- **CRM callback authorization FIXED / workflow PARTIAL:** legacy attendance and financial callbacks trusted group/enrollment IDs from buttons. Callbacks now require a verified teacher/platform admin, private chat and group ownership. Legacy tuition receipt buttons cannot safely identify or atomically consume a receipt and are blocked with a message directing the user to the LMS panel; a receipt-specific, auditable, idempotent replacement remains open. This is an intentional temporary behavior change for security.
- **SEC-004 PARTIAL:** existing SSO token expiration, row locking, single-use handling, Mini App HMAC comparison and webhook-secret checks were inspected. Tests exercise selected paths, but the complete replay, concurrent webhook, token/session, CSRF and notification-deduplication audit is not finished. No claim of complete authentication security is made.
